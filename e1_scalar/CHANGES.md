## New code written for E1 (outside the prior package)

- `e1_methods.py`
  - `mp_lu_solve`: mpmath LU with partial pivoting on Python lists of `mpf` (exact
    float32 -> mpf conversion) at a declared number of decimal digits (100 for the
    reference, 120 for the audit subset). The prior package's `tpir.experiments.highprec`
    used `mp.lu_solve` on `mp.matrix`, which is much slower; the algorithm is the same
    (LU with partial pivoting).
  - `mp_residual_inf`: 100-digit `||b - A x||_inf` of a final FP32 iterate.
  - `metrics_fp64`: eta / omega / relres / forward errors from the exact stored FP32 A, b.
  - `gmres_fp32` + `gmres_ir`: left-preconditioned GMRES-IR (Carson & Higham 2018
    Alg. 8.1; Higham 2019 Alg. 3.1) reusing the prior package's FP16 factors
    (`tpir.arithmetic.lu_factor`), its FP16 initial solve (`scaled_solve`, identical to
    `hsd`'s x_0), its sequential residual model (`residual`) and its triangular solves
    applied in a declared precision (`LU.solve(..., arithmetic_bits=64|32)`).
    The prior package did not implement GMRES-IR (its README says so explicitly).
- `run_e1.py`: grid driver (multiprocessing over cases), references, audits, metrics,
  histories, `cases.jsonl` / `trials.jsonl` / `methods.json` / `summary.md`.

## Reuse of the prior generator

Problems are generated by the prior `tpir.problems.make_problem` with
`family='spectral', rhs='random'` (geometric singular values, U and V from numpy QR of
Gaussian matrices, A formed in FP64 and stored as FP32, b = standard normal FP64 rounded
to FP32). The procedure is recorded verbatim in every `cases.jsonl` record (`generator`).
Note: numpy's QR does not sign-correct the diagonal of R, so U, V are "Haar up to
column signs"; this is the prior lab's convention and was kept for comparability.
